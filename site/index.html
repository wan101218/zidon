zidon 把你手工做的发版宣传（Release Notes、社交动态、Awesome 提交、issue 回复）拆成两半： 本地小模型写草稿，云端 Actions 负责发布。本机几乎不耗性能，账号密码也从不落到本地脚本里。

整条链路

  1. 本地生成草稿 你 Ollama + 小模型只写文字：发版说明、社交文案、Awesome 条目前、issue 回复。没装模型会回退到模板，链路照样通。
  2. 人工审批 你 · 约 1 分钟 promoter review 逐条过：批准 / 改一句 / 丢弃。未审批的草稿被 .gitignore 拦住，发不出去。
  3. git push 你 只有 content/approved/ 会被推到云端。
  4. 云端自动发布 GitHub Actions 校验内容 → 建 Release → 发社交动态 → 部署落地页 → 提交 IndexNow → 发布到 PyPI / npm / Docker Hub。
  5. 外部世界发现你 自动 搜索引擎收录、包管理器上架、社交平台触达，最终都回到同一个落地页。
  6. issue 回复闭环 你 · 点确认 本地拉取 issue 写回复草稿，你确认后才发出——不做自动秒回，避免答错和刷屏。

为什么所有对外内容都要人工点一下？ 自动秒回和自动群发看起来省事，但答错一次的成本远高于花一分钟确认。 这套设计把「机器快」用在写草稿上，把「责任」留给人。

它刻意不做的事

不碰你的密码

本地脚本不直连任何社交账号；token 只存在 GitHub Secrets 里，云端调官方 API。

不骚扰别人

没有自动关注、自动私信、群发评论功能，配置里这些开关被写死为关闭，CI 会拦截篡改。

不刷屏

同一平台两次发帖有最小间隔，每日有上限；同一内容靠指纹去重，重跑工作流也不会重复发。

不编造数据

提示词明确禁止虚构功能、用户数和他人评价；超长文案在生成时就截断，CI 里再断言一次。
